## Coverage / OK-verified groups

- **Categories (10/10)**: slug, label, sort_order, is_archived all identical old→new, including the single archived category `vyvedennye` ("Выведенные", sort_order 9) that drives the kit's "В карте"/"Выведенные" tab split (`SPIRIT_GROUPS` vs `SPIRIT_GROUPS_ARCHIVED` in `mapBundle.ts`). Verified by direct query on both DBs.
- **Entry counts per category**: old vs new match exactly for all 10 categories (agavovye 8, viski 13, dzhin 5, brendi 4, kreplenye-vina 5, amaro 3, rom 7, likery 6, vino 5, vyvedennye 18 = 74 total both sides).
- **`abv`**: 74/74 non-blank in old and new; `Numeric(5,2)` has no precision loss (no source value has more than 1 decimal digit); `is_alcoholic`-style "Non Alc" edge case doesn't apply to this table (spirits are always alcoholic).
- **`brand`**: passed through verbatim including multi-value semicolon-joined names (ids 6, 29, 73 — `"Bodega San Isidro; BarSol"` etc.) — not re-split or scrambled.
- **`fact`, `features`, `flavour`, `name`, `img`, `slug`, `sort_order`, `created_at`**: straight passthrough columns, unchanged; `img` is NULL for all 74 rows in both old and new (never populated in prod), confirmed via count query.
- **`cocktail_pairings` → `pairings`**: this was a genuine **bug fix**, not a loss — the old frontend read `entry.cocktail_pairings` but `ContentContext`'s normalizer only ever set `entry.cocktailPairings`, so "В коктейлях" never rendered in prod despite 45/74 rows having data (documented in `frontend-inventory.md` §5). New pipeline (`cocktail_pairings` DB column → `pairings` in `SpiritEntryOut`/bundle → `s.pairings` in kit's `SpiritDetail`, "В КОКТЕЙЛЯХ" section) renders it correctly — confirmed 45/74 non-null `pairings` present and wired through in `bundle.json`.
- **`region`**: confirmed old data model never had a distinct region column/value — `SpiritSheet.jsx`'s "Страна / регион" label was just a label on the single `country` field. `mapBundle.ts::mapSpirit` setting `region: undefined` is correct, not a loss (there is nothing to map).
- **Meta string** (`COUNTRY · NN% ABV` in `mapBundle.ts::spiritMeta`, used by `SpiritRow`/`SpiritDetail`): old UI never had an equivalent single "meta" string — the old card showed `flavour` (tagline) + separate ABV chip + separate price chip; the old detail sheet showed ABV/price as pills and country only inside the "Страна / регион" section. The new synthesized meta string is a reasonable UI simplification; its only downstream effect worth noting is that `flavour` and price are no longer part of the at-a-glance view (see SP-1, SP-2).
