## OK — verified, no regression

- **Categories**: all 7 `kitchen_categories` rows present old↔new with identical `slug`/`label`/`sort_order` (`goryachee-i-zakuski, supy, salaty, sendvichi, doski, sladkoe, sousa`). Category order (distinct sort_order values 0-6) is preserved correctly in the bundle.
- **Dish counts per category**: old vs new match exactly for every category — `1:10, 2:2, 3:2, 4:4, 5:5, 6:3, 7:7` = 33/33 total, both DBs.
- **slug / name / img→photo / description / serving / interesting_facts→fact / created_at**: pass through unchanged, verified on samples (ids 1, 12, 21-27, 36) and via row counts.
- **`price_amount` parsing (`parse_price`)**: correct for every populated row (e.g. `'430₽'→430.00`), nulls correctly preserved as null (not defaulted) for the 4 sauce rows with no old price — zero parse failures across all 33 rows (checked via `price_amount IS NULL AND price_raw IS NOT NULL`, 0 rows).
- **`weight_g` parsing (`parse_weight_g`)**: all 33 raw weight values are bare integers (no `"280/50"`-style composites in this dataset, confirmed by reading every row) — exact 1:1 match old string → new int, zero nulls.
- **`timing_min_low/high` parsing (`parse_timing`)**: correctly extracts both bounds for the one range value (`'10-12'→(10,12)`) and single values (`'10'→(10,10)`); the 13 blank old values correctly become `(NULL, NULL)`. Zero parse failures.
- **`kcal_portion/protein_g/fat_g/carb_g` parsing (`parse_nutrition`)**: verified against raw text for the 29 majority-format dishes (regex A, e.g. id 1: `503/29.0/6.8/75.7` ✓) and the 4 minority-format dishes (regex B, ids 22/23/26/27, e.g. id 22: `195.20/0.16/18.62/5.96` ✓ against raw `"...0,16 ж 18,62 у 5,96 195,2 ккал"`) — every portion number survives, zero parse failures across all 33 dishes.
