# Аудит текущей системы klktv-cocktails (прод)

**Дата:** 2026-07-19
**Объём:** прод-репозиторий (backend FastAPI, frontend React 18), живая прод-БД (Postgres 15, 28 таблиц, ~1150 строк).
**Метод:** формальный read-only аудит четырьмя параллельными агентами. Прод-код и прод-БД не изменялись.
**Цель:** решить, что оставить и почистить, а что не тащить в новую версию; подтвердить, что все данные переносимы.

Детальные отчёты:
- [details/backend.md](details/backend.md) — код бэкенда, баги, вердикт keep-vs-rewrite
- [details/frontend-inventory.md](details/frontend-inventory.md) — полный инвентарь фич (чек-лист для ребилда)
- [details/database.md](details/database.md) — схема и качество данных, вердикт keep-vs-evolve
- [details/security.md](details/security.md) — безопасность, ранжированные находки

## 1. Вердикты

| Слой | Вердикт | Обоснование |
|---|---|---|
| **Бэкенд** | **KEEP-AND-CLEAN** | Ядро здоровое: чистое разделение models/schemas/routers, корректная ролевая авторизация, read-запросы eager-load'ятся (нет N+1), полный CRUD и safety-rails на месте. Проблемы — легаси-наросты и операционные хаки поверх нормальной архитектуры, снимаются точечно. Переписывание воспроизведёт 40+ эндпоинтов и ту же схему ради малого выигрыша и реального риска регрессий. |
| **Схема БД** | **EVOLVE** | Реляционный скелет хорош (нормализованные справочники, M:N-таблицы, FK с продуманным ON DELETE, уникальные slug'и, audit-колонки). Но «плоть» грязная: структурные данные хранятся свободным текстом, есть дублирующиеся подсистемы. Свежая БД — момент это починить, не ломая скелет. |
| **Фронтенд** | **REBUILD на UI Kit** | Голый JSX без дизайн-системы и типизации, роутинг чистым стейтом. Заменяется блоком `block-cocktail-guide` из кита. Инвентарь фич — мерило полноты. |
| **Данные** | **PRESERVE (через ETL)** | Целостность чистая, объём крошечный, дублей slug'ов и сирот нет. Сохранить всё полностью совместимо с эволюцией схемы, если при ETL держать сырой текст в `*_raw`. |

## 2. Критичное — обязательно починить, НЕ тащить в новую версию

### Безопасность (из security.md)
- **C-1. Пароли всех 12 юзеров (включая админа) в `seed.py` открытым текстом** и переписываются в БД при **каждом старте контейнера** (`Dockerfile:30` гоняет `python seed.py`). Админский пароль нельзя сменить через UI — он откатывается на дефолтный при каждом деплое. → Сид только бутстрап-админа из env, только когда юзеров нет; никогда не переписывать существующие хеши; убрать сид из загрузочного пути; ротировать утёкшие пароли; вычистить из git-истории.
- **C-2. Захардкоженный fallback `SECRET_KEY`** (`config.py:3`) без fail-fast. При незаданной env-переменной любой подделывает админ-токен публичным ключом из репо. → Падать на старте, если `SECRET_KEY` не задан или равен dev-значению.

### Потеря данных (из backend.md)
- **HIGH-1. Сид на каждом старте** сбрасывает роль/пароль/имя 12 сид-юзеров → правки админа в UI молча откатываются при рестарте. (Та же причина, что C-1.)
- **HIGH-2. Переименование slug'а сиротит прогресс.** `learning_progress` завязан на `(user_id, kind, slug)` без FK; любой admin PATCH меняет slug и не мигрирует строки прогресса → у всех, кто отметил позицию «знаю», она снова «не изучено», строки-сироты копятся навсегда. → В новой схеме дать `learning_progress` реальную целостность и мигрировать строки при переименовании.

## 3. Не тащить в новую версию (легаси-наросты)

**Бэкенд:**
1. Сид-как-миграция в `CMD` (переплетает провижн юзеров, импорт контента, cleanup и backfill на пути раздачи) — сделать одноразовым, вне boot.
2. Рабочие дефолты `SECRET_KEY`/`DATABASE_URL` в `config.py` — заменить на required + fail-fast.
3. Нет миграций: `create_all` + ручной список `ADD COLUMN` (собственный комментарий кода: «за ~10 записей — переходи на Alembic», уже 7+1). → **Завести Alembic.**
4. Мёртвая таблица `classic_progress` + её data-migration + скрытые легаси-роуты `me.py` (superseded `learning_progress`). → Удалить.
5. `admin.py` — 731 строка, 8 типов копипаст-CRUD; блок конфликта slug'а продублирован 6×. → Обобщённая slug-CRUD-фабрика (−~500 строк, и фикс HIGH-2 в одном месте).
6. Манифест `pyproject.toml` не содержит `python-multipart` и `Pillow` (захардкожены в Dockerfile) → сборка из манифеста падает `ModuleNotFoundError: PIL`; нет `uv.lock`. → Починить манифест, закоммитить лок.
7. Логаут не чистит cookie в cross-origin (нет `secure`/`samesite` в `delete_cookie`) → юзер остаётся залогинен до истечения токена.
8. Разное: `int(payload["sub"])` даёт 500 вместо 401 на битом токене; `mark_learned` без upsert (гонка → 500); миграции колонок и данных в одной транзакции (аборт одной откатывает всё); мёртвый claim `role` в JWT.

**Схема/данные (из database.md):**
9. **ABV в 4 несовместимых форматах** (`12.0%` / `40` / `6,4 Alc` / `Non Alc`), всё varchar. → `abv NUMERIC`.
10. **Цена свободным текстом**: `430₽` vs `430 ₽`; у спиритов 18/74 нечисловые с размером порции и переносами строк (`500р\nза 100мл`). → amount + currency + serving_ml.
11. **КБЖУ (nutrition) свободным текстом** в двух форматах. → явные колонки Б/Ж/У/ккал (на порцию и на 100г). Плюс `weight_g`, `timing` минуты как int/диапазон.
12. **Три пересекающихся поля происхождения спирита** (`brand` / `country` / `brand_country`): незавершённый рефакторинг — целевые колонки добавлены, но не заполнены; в `country` мусор `регион:Испания`; URL'ы зашиты в прозу `brand_country`; `source_url` пуст на 97%. → Разобрать, вынести URL, ретайрнуть `brand_country`.
13. **Две параллельные подсистемы безалко**: `zero_*` (1+2 строки) vs `zc_*` (2+6, надмножество) — обе как отдельные разделы. → **Продуктовое решение** (см. §5).
14. Три почти одинаковые таблицы `*_details` (cocktail/zero/zc) — унифицировать.
15. `glass_label_override` используется 1 раз из 94 строк — параллельная free-text колонка на 4 таблицах ради одного края. → Один fallback.
16. Мёртвый флаг `categories.is_visible` (true у всех 6); `zc_drinks.is_carbonated` nullable без дефолта; `tags` без `label` (в отличие от остальных справочников).
17. Тест-мусор в проде: `test-tag`, флейвор `ДОБАВЛЕНО ИЗ UI`, дескрипторы `Тестовый`/`Обновлённый`; опечатки `Ирдандия`×3, `Габа.`. → Вычистить при ETL.

**Фронтенд (из frontend-inventory.md) — «невидимые» фичи, решить судьбу:**
18. Секция спирита «В коктейлях» не рендерится из-за рассинхрона поля (`cocktail_pairings` vs `cocktailPairings`) — данные есть, редактируются в админке, но не показываются. → Тривиальный фикс, восстановить.
19. Таймлайн истории коктейлей (`timeline_entries`, 8 строк) грузится в бандл, есть CSS, но нигде не рендерится — латентная/вырезанная фича. → **Продуктовое решение**: делаем раздел «История» или отказываемся.
20. Дубликат `Upcykle Cola` как cocktails (`upcyklecola`) И zc_drinks (`upcykle_cola`), с продублированными detail-блоками; zc-строка помечена `is_alcoholic=TRUE` внутри безалко-подсистемы. → Реконсилиация при слиянии безалко.

## 4. Что сохранить (сделано правильно)

Ролевая авторизация на уровне роутеров без пропусков; роль читается из БД, не из JWT-claim (мгновенная деактивация/смена роли); нет IDOR (прогресс скоупится по `user.id`); safety-rails юзеров (нельзя удалить/разжаловать себя, снять последнего админа); нет SQL-инъекций (ORM); нет alg-confusion в JWT; аплоады обезврежены (Pillow re-encode, санитайз имени, allowlist расширений — нет path traversal); `resize-existing` не SSRF; нормализованный реляционный скелет с честными FK; eager-loaded read-путь; единый bundle-эндпоинт `GET /api/content`; полный инвентарь фич (см. detail).

## 5. Открытые продуктовые решения (нужен вход владельца)

1. **Безалко: слить или оставить два раздела?** Прод показывает «Non Alco» (`zero`, 1 позиция) и «Zero Culture» (`zc`, 2 позиции) отдельно; `zc_drinks` — надмножество. Слияние требует реконсилиации дубля Upcykle Cola.
2. **История/таймлайн:** делаем раздел «История» (8 готовых записей) в новой версии или отказываемся?

## 6. Приоритет работ для v2

1. Миграция данных прод → новая БД с ETL (re-type + де-дуп + чистка), сырой текст в `*_raw`, скрипт идемпотентный/повторяемый (прод живёт параллельно).
2. Бэк keep-and-clean: Alembic-baseline эволюционной схемы; убрать сид из boot + env-бутстрап админа; required-секреты + fail-fast; slug-CRUD-фабрика + фикс миграции прогресса; починить манифест/лок; мелкие корректности.
3. Фронт с нуля на `block-cocktail-guide`: пройти инвентарь фич как чек-лист; восстановить «невидимые» фичи по решению из §5.
4. Безопасность: rate-limit логина, парольная политика, закрыть Swagger в проде, ревокация токенов, CSRF на мутации/аплоад.
5. Админка на ките — отдельным этапом.
